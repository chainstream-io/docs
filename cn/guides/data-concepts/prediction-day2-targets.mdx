# Prediction Activities Day2 目标与验收目录

## 完成目标

1. 基于远程 `origin/main` 创建 Day2 实施分支，隔离 Day1 工作区改动。
2. 为 Polygon prediction trades / settlements 生成 wallet-token activity 明细，写入 ClickHouse activity 表。
3. REST API 新增 `GET /v1/prediction/events/{event_slug}/activities`，返回字段不少于 Future.news activity 字段集合。
4. OpenAPI 注册 prediction activity path、query params、response schema，并用 schema 测试锁定字段完整性。
5. Realtime 使用短 channel：
   - event activity: `pred:evt:{eventSlug}:act`
   - token activity: `pred:tok:{tokenId}:act`
6. Realtime activity payload 使用短字段并由 SDK 反序列化为完整模型。
7. SDK 增加 prediction activity 订阅方法，channel 构造使用枚举，不手写拼接。
8. Activity Kafka topic retention 为 1 天；ClickHouse activity 明细保留 3 天；topic map Redis TTL 为 1 天。
9. 首屏缓存增加开关，默认 `PREDICTION_FIRSTSCREEN_CACHE_ENABLED=false`，TTL 预设 15 秒，默认不写缓存。
10. 部署顺序明确：先 PR，由 reviewer 确认后才能合并；合并后拉最新 `origin/main`，再对 services 和 SDK 打 tag。

## 验收目录

### 数据与存储

- `polygon_prediction_wallet_token_activities_local` / distributed / archive / realtime view 已有 DDL。
- trades sink 会为 buy/sell 生成 activity row。
- settlements sink 会为 redeem/split/merge 生成 activity row，其中 redemption 映射为 `redeem`，split/merge 映射为 `inventory_adjust`。
- activity row 包含 `activityId`、`amount`、`assetIds`、`blockNumber`、`conditionId`、`eventSlug`、`marketId`、`marketQuestion`、`outcome`、`outcomes`、`price`、`quantity`、`seqIndex`、`taker`、`timestamp`、`tokenId`、`txHash`、`type`。
- Kafka key 使用 `taker:tokenId`，activity topic retention 为 `86400000` ms。
- ClickHouse activity TTL 为 3 天。

### REST API

- OpenAPI path 存在：`/v1/prediction/events/{event_slug}/activities`。
- Query 支持 `cursor`、`limit`、`token_id`、`market_id`、`condition_id`、`wallet`、`activity_type`、`order`。
- `market_id` 与 `condition_id` 同时传入且不一致时返回 bad request。
- 当前 event allowlist 为 `world-cup-winner`。
- OpenAPI 单测验证 activity schema 完整字段。

### Realtime 与 SDK

- Realtime channel 不带 `chains.` 前缀。
- Payload 外层使用 `a`，内部字段缩写，如 `id`、`amt`、`cid`、`mid`、`tid`、`tx`、`ty`。
- TypeScript SDK 方法：
  - `subscribePredictionEventActivities`
  - `subscribePredictionTokenActivities`
- Rust SDK 方法：
  - `subscribe_prediction_event_activities`
  - `subscribe_prediction_token_activities`
- SDK activity type 使用枚举：`buy`、`sell`、`redeem`、`inventory_adjust`。

### 缓存

- Metadata cache TTL 维持 1 天。
- Topic map cache TTL 为 1 天。
- Firstscreen cache 默认关闭；如果后续打开，默认 TTL 为 15 秒，并需补缓存命中率与陈旧数据监控。

### 部署

- aggregation-pipelines：提 PR；review 通过后，先创建/确认 ClickHouse activity 表，再创建/更新 Kafka topic retention，再部署 prediction trades/settlements sink。
- services：提 PR；review 通过并合并后拉最新 `origin/main`；从 main 打 tag；部署 API。
- chainstream-sdk：提 PR；review 通过并合并后拉最新 `origin/main`；从 main 打 tag；发布 SDK。
- 部署后验证 OpenAPI YAML、REST 首页、cursor 下一页、realtime event channel、realtime token channel、SDK 订阅解析。
